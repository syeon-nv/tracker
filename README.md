# Tracker 빌드/배포 가이드

이 저장소는 `index.html` 하나(HTML+CSS+JS 단일 파일)로 돌아가는 앱을
Electron으로 감싸서, 다른 사람에게 나눠줄 수 있는 프로그램(Windows: `.exe`
설치 파일, macOS: `.dmg`)으로 만드는 프로젝트입니다.

프로그래밍을 몰라도 아래 순서대로 명령어만 그대로 따라 치면 됩니다.

- `index.html` — 앱 전체(화면, 로직)
- `main.js` — Electron 메인 프로세스(창 생성, 파일 저장, 시작프로그램 등록 등)
- `preload.js` — 렌더러(index.html)와 메인 프로세스를 안전하게 이어주는 다리
- `icon.ico` / `icon.icns` — 앱 아이콘(Windows용 / macOS용)
- `package.json` — 빌드 설정, 의존성 정의
- `scripts/sync-version.js` — 빌드 전에 버전 번호를 자동으로 맞춰주는 스크립트

**참고**: 예전에는 앱 이름이 "AngleQuest"였는데, 지금부터는 "Tracker"로
통일했습니다. 이미 예전 이름(AngleQuest)으로 만든 설치 파일을 써본 적이
있다면, 컴퓨터 안에 데이터가 저장되는 폴더 이름도 앱 이름을 따라가기
때문에 이번에 새로 설치하면 데이터가 빈 상태로 새로 시작됩니다(예전
데이터가 지워지는 건 아니고, 다른 폴더에 그대로 남아있습니다). 아직
아무에게도 배포하지 않았다면 신경 쓰지 않아도 됩니다.


## 0. 처음 한 번만 하면 되는 준비

1. **Node.js 설치**: https://nodejs.org 에서 LTS 버전을 받아 설치합니다.
   (Windows든 macOS든 동일한 사이트에서 자기 OS에 맞는 설치 파일을 받으면 됩니다.)
2. 설치가 끝나면 확인:
   - Windows: 명령 프롬프트(cmd) 또는 PowerShell을 열고 `node -v` 입력
   - macOS: "터미널" 앱을 열고 `node -v` 입력
   - 버전 번호(예: `v20.x.x`)가 나오면 정상입니다.
3. 이 프로젝트 폴더 안에서 아래 명령어를 한 번 실행해 필요한 패키지를
   설치합니다(인터넷이 연결되어 있어야 합니다).

   ```
   npm install
   ```

   시간이 좀 걸릴 수 있습니다(1~5분). 완료되면 `node_modules` 폴더가
   생깁니다.

이후로는 새로 빌드할 때마다 이 과정을 반복할 필요 없이, 바로 아래 1번(테스트
빌드)이나 2번(배포용 빌드)으로 넘어가면 됩니다.


## 1. 내 컴퓨터에서 테스트로 실행/빌드해보기

배포하기 전에 먼저 앱이 잘 도는지 내 컴퓨터에서 확인하고 싶다면:

```
npm start
```

이 명령어는 설치 파일을 만들지 않고, 지금 바로 앱 창을 띄워서 확인만
해보는 용도입니다. 창을 닫으면 그냥 종료됩니다.

(참고: 이 폴더에는 "포터블 폴더" 형태로 미리 만들어보는
`npm run build`(Windows) / `npm run build:mac`(macOS) 명령어도 남아있습니다.
설치 과정 없이 폴더째로 옮겨서 실행해보고 싶을 때만 쓰면 되고, **실제
판매·배포는 아래 2번의 방식을 쓰는 걸 권장**합니다.)


## 2. 다른 사람에게 배포(판매)할 프로그램 만들기

여기서 만드는 파일은 받는 사람이 "설치 프로그램"처럼 더블클릭 한 번으로
설치할 수 있는 정식 배포판입니다. **Windows용은 Windows에서, macOS용은
반드시 실제 Mac에서 만들어야** 합니다(다른 OS에서는 만들 수 없습니다 —
자세한 이유는 macOS 항목 참고).

### 2-1. Windows용 설치 파일 만들기 (64비트 + 32비트 동시 생성)

**Windows 컴퓨터에서** 이 폴더를 열고, 명령 프롬프트나 PowerShell에서:

```
npm run dist:win
```

이 명령어 한 번으로 **64비트(x64)용과 32비트(x86/ia32)용 설치 파일이 둘 다**
만들어집니다. 따로 명령어를 나눠서 칠 필요가 없습니다. 완료되면
`dist-installer` 폴더 안에 아래와 같은 파일들이 생깁니다.

```
dist-installer/Tracker Setup 1.0.0-x64.exe    ← 대부분의 최신 Windows용
dist-installer/Tracker Setup 1.0.0-ia32.exe   ← 오래된 32비트 Windows용
```

**어느 걸 전달해야 하나요?**
- 요즘 파는 Windows 컴퓨터는 거의 다 64비트입니다. 잘 모르겠다면
  **`-x64` 파일을 전달**하면 됩니다.
- 상대방이 아주 오래된 컴퓨터(32비트 Windows)를 쓰고 있다고 특별히
  말한 경우에만 `-ia32` 파일을 대신 전달하세요.
- 확실하지 않다면 두 파일을 다 전달해도 되고, 받는 사람이 자기 컴퓨터에
  맞는 걸로 골라 실행하면 됩니다(설정 → 시스템 → 정보에서 "시스템 종류"
  확인 가능).

받은 사람은:

1. 받은 `.exe` 파일을 더블클릭
2. 설치 마법사가 뜨면 설치 위치를 확인하고 "설치" 진행
3. 설치가 끝나면 바탕화면/시작 메뉴에 "Tracker" 아이콘이 생기고, 그걸
   클릭해서 실행

Node나 Electron을 따로 설치할 필요가 전혀 없습니다(필요한 게 전부
설치 파일 안에 포함돼 있습니다).

**서명 관련 경고 안내**: 코드 서명(아래 2-3 참고)을 하지 않은 상태라면,
받은 사람이 처음 실행할 때 Windows가 "Windows의 PC 보호" 또는
"알 수 없는 게시자"라는 경고 화면을 띄울 수 있습니다. 이건 바이러스라서
그런 게 아니라, 아직 "이 프로그램을 만든 사람이 누구인지 인증서로
확인되지 않았다"는 뜻입니다. 경고 화면에서 "추가 정보" → "실행"을
누르면 정상적으로 설치가 진행됩니다. 무료로 나눠주는 정도라면 이 경고를
받는 사람에게 미리 안내해주는 것만으로 충분하고, **돈을 받고 파는
제품이라면 2-3번의 코드 서명을 준비하는 걸 권장**합니다.

### 2-2. macOS용 설치 파일 만들기 (Intel + Apple Silicon 동시 생성)

**반드시 실제 Mac 컴퓨터에서** 진행해야 합니다. (Windows에서는 macOS용
`.dmg`/`.app`을 만들 수 없습니다 — Apple이 자기 운영체제 전용 도구로만
패키징을 허용하기 때문입니다.)

Mac의 "터미널" 앱에서 이 폴더로 이동한 뒤:

```
npm install
npm run dist:mac
```

(맥에서 처음 여는 거라면 `npm install`부터 다시 한 번 해줘야 합니다 —
운영체제마다 필요한 내부 파일이 달라서 그렇습니다.)

이 명령어 한 번으로 **Intel Mac용과 Apple Silicon(M1/M2/M3 등) Mac용
설치 파일이 둘 다** 만들어집니다. 완료되면 `dist-installer` 폴더 안에
아래 파일들이 생깁니다.

```
dist-installer/Tracker-1.0.0-x64.dmg     ← Intel Mac용
dist-installer/Tracker-1.0.0-arm64.dmg   ← Apple Silicon(M1/M2/M3 등) Mac용
```

**어느 걸 전달해야 하나요?**
- 2020년 이후에 나온 맥은 대부분 Apple Silicon(M1 이상)입니다. 확인하는
  법: Apple 메뉴 → "이 Mac에 관하여"에서 칩 종류를 보면 됩니다.
  "Apple M1/M2/M3..."라고 써있으면 `-arm64`, "Intel"이라고 써있으면
  `-x64`를 전달하면 됩니다.
- 확실하지 않다면 두 파일을 다 전달해도 됩니다.

받은 사람은:

1. 자기 Mac에 맞는 `.dmg` 파일을 더블클릭해서 열기
2. 열린 창에서 "Tracker" 아이콘을 "Applications" 폴더 아이콘 위로
   드래그
3. Launchpad나 Applications 폴더에서 "Tracker" 실행

**서명 관련 경고 안내**: macOS는 Windows보다 더 엄격합니다. 서명 안 된
앱을 처음 열면 "확인되지 않은 개발자입니다"라는 경고와 함께 실행이
막힙니다. 이럴 땐 받은 사람이 Finder에서 앱을 **우클릭(또는 control+클릭)
→ 열기**를 한 번 눌러줘야 합니다(그다음부터는 평소처럼 더블클릭으로
바로 실행됩니다). 이 부분도 무료 배포라면 안내만 해주면 되고, **판매용
이라면 2-3번의 Apple 개발자 서명·공증을 준비하는 걸 강력히 권장**합니다
(공증 없이 macOS에 배포하면 구매자 입장에서 "바이러스 아니냐"는 의심을
사기 쉽습니다).

### 2-3. (판매 전 준비하면 좋은 것) 코드 서명

지금 방식(2-1, 2-2)으로도 배포·설치는 문제없이 됩니다. 다만 사이트에
올려서 정식으로 판매할 계획이라면, 아래 서명 절차를 준비하는 걸
권장합니다 — 앞서 설명한 경고 화면이 사라지고, 구매자 신뢰도가
올라갑니다.

- **Windows**: 코드 서명 인증서(DigiCert, Sectigo 등에서 구매, 신원 확인
  필요)를 준비하면 SmartScreen 경고가 줄어들거나(EV 인증서는 거의 즉시
  사라짐) 사라집니다.
- **macOS**: Apple Developer Program(연회비 있음)에 가입해서 Developer ID
  인증서로 서명 + Apple 공증(notarization)까지 마쳐야 경고 없이 바로
  실행됩니다.

인증서를 준비하게 되면, `package.json`의 `build.win`/`build.mac` 설정에
서명 정보를 추가해 드릴 수 있으니 그때 다시 요청해주세요.


## 3. 버전업 하는 방법

새 버전을 낼 때마다 아래 **딱 한 줄**만 실행하면 됩니다.

```
npm version 1.1.0
```

(숫자는 원하는 새 버전 번호로 바꾸면 됩니다. 지금은 `1.0.0`이니, 다음
버전은 보통 `1.0.1`(자잘한 수정), `1.1.0`(기능 추가), `2.0.0`(큰 변경)
중 상황에 맞는 걸 고르면 됩니다.)

이 명령어 하나가 자동으로 다음을 해줍니다:

- `package.json`의 `"version"` 값을 새 번호로 바꿔줍니다.
- 이후 `npm run dist:win` 또는 `npm run dist:mac`을 실행하면, 빌드
  시작 전에 `scripts/sync-version.js`가 자동으로 실행되어 `index.html`
  안의 버전 표시 부분도 방금 정한 새 번호로 맞춰줍니다. **따로 손으로
  파일을 열어서 고칠 필요가 없습니다.**
- 새로 만들어지는 설치 파일 이름에도 새 버전 번호가 자동으로 들어갑니다
  (예: `Tracker Setup 1.1.0-x64.exe`, `Tracker Setup 1.1.0-ia32.exe`).

정리하면, 버전업 → 배포 전체 순서는 이렇게 됩니다:

```
npm version 1.1.0     (버전 번호만 올리기)
npm run dist:win       (Windows용 새 설치 파일 만들기)
```

(macOS용도 새로 만들려면 실제 Mac에서 `npm run dist:mac`을 실행하면
됩니다.)

앱을 실행 중인 사용자가 이 새 버전으로 업데이트하면, 앱이 "이전 버전 →
새 버전으로 업데이트됐어요" 안내 모달을 자동으로 보여줍니다(추가로
설정할 것은 없습니다).

**참고**
- `npm version` 없이 그냥 `npm run dist:win`만 실행해도 빌드는 되지만,
  이 경우 이전 버전 번호가 그대로 들어갑니다. 새 버전을 낼 때는 꼭
  `npm version`부터 먼저 실행해주세요.
- `sync-version` 스크립트는 여러 번 실행해도 안전합니다(항상 그
  시점의 `package.json` 버전으로 덮어쓸 뿐이라, 중복 치환 같은 문제가
  생기지 않습니다).
